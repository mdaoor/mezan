4. Text normalization

WER compares strings; strings differ for reasons that are not recognition errors. Normalization maps both reference and hypothesis into a canonical form before alignment. It is the single largest source of non-comparable numbers in published ASR results: a third-party summary of the Open Universal Arabic leaderboard says it strips punctuation and diacritics and standardizes numerals, the QCRI Arabic+English leaderboard removes diacritics, and Cohere's normalizer additionally transliterates numerals, removes tatweel and applies NFKC — so scores from these protocols are not directly comparable. community / vendor-reported The Open ASR Leaderboard paper describes its English normalizer as closely following Whisper's (casing, punctuation, number conversion, spelling standardization, filler-word removal). verified

4.1 Principles

  1. Same normalizer on reference and hypothesis, always. Normalizing only one side manufactures errors.
  2. Version and print it. The normalizer kind and version are part of the run's identity; its rules are printed in every report. Changing a rule creates a new run.
  3. Normalize away what the downstream use does not care about (diacritics for search/analytics) and keep what it does (digits if downstream parses amounts; diacritics if you sell vowelized output).
  4. Never mutate stored text. Keep raw hypotheses and references; normalization happens at scoring time so you can re-score under a different policy.
  5. Report raw and normalized WER side by side. The gap shows how much a candidate relies on formatting luck; a model with excellent normalized WER but poor raw WER may need a post-processing step.

4.3 Pitfalls specific to Arabic–English code-switching

  • Script of English words. The same spoken English term can be written meeting or ميتنج. If the reference uses Latin script and the model transliterates (or vice versa) every such word is an error although it was recognized. Decide the policy in the style guide, then measure it explicitly with an English-term preservation metric (§5.4) rather than hiding it in WER. If transliteration is acceptable, use multi-reference or transliteration-aware scoring (PolyWER; §5.6).
  • Clitic attachment. Arabic conjunctions and prepositions attach to words (والكتاب = "and the book"); one wrong clitic makes the whole token wrong. WER is therefore harsher on Arabic than on English for the same acoustic error. Always report CER next to WER.
  • Output style differences between models. Some models emit diacritics (Jais-ASR offers optional diacritization), punctuation, or sentinel tokens (the Jais adapter in Mizan maps [IFM-NoTranscript] to "no speech"). Normalization and adapter rules must absorb these so style is not scored as error.
  • Numbers. Spoken numbers appear as words or digits depending on the model. Without inverse text normalization, WER penalizes the formatting difference. Either normalize both to one form or add a numbers-specific accuracy metric.
  • Dialect spelling. Where annotators disagree systematically, derive a rule from the IAA disagreements instead of deciding case by case.
Best practice Keep a small "normalizer golden test" (Mizan ships four fixtures) and extend it with every rule change. Rule changes must be reviewed like code, because they move every historical number.

5. Accuracy metrics and algorithms

5.1 Edit-distance error rates

All error-rate metrics start from a minimum-cost alignment between reference tokens and hypothesis tokens (Levenshtein/dynamic programming; unit cost for substitution, deletion and insertion). Let S, D, I be the counts of substitutions, deletions, insertions, C the correct matches, and N = S + D + C the reference length.

WER = (S + D + I) / N may exceed 100% (insertions are unbounded) CER = same, on characters (state whether spaces count; Mizan counts them) MER = (S + D + I) / (S + D + I + C) bounded in [0, 1] WIL = 1 − (C / N_ref) · (C / N_hyp) word information lost (Morris et al. style)

Alignment ties. Several alignments can have the same minimum cost; the total error count is identical but the split between S, D and I (and any attribution to scripts) can differ. Use one alignment engine for every metric (Mizan uses jiwer throughout) so script-split numbers add up to the total.

5.3 Aggregation rules (these change decisions)

  • Micro-average over words (corpus level), not over segments: a 30-word segment must weigh more than a 2-word one.
  • Per-stratum values are also corpus-level within the stratum (Mizan: Σerrors / ΣN inside each slice), and the stratum n must be shown so thin slices are not over-read.
  • Metrics that do not apply to a segment must not contribute (e.g. English-term preservation on a segment with no English; hallucination rate on speech segments). Mizan marks them non-applicable and aggregates only over applicable ones.
  • Empty references (true silence) have N = 0: every emitted word is an insertion. Do not skip them — they are exactly where some models fail.

5.4 Code-switching specific metrics

Research on Arabic–English code-switching (e.g. the Egyptian ArzEn benchmarking study) reports that standard WER/CER fail to capture cross-transcription and orthographic variation, and evaluates MER and WIL alongside them. verified (abstract-level) A vendor blog reports an example where overall WER improved 1.69 points while switch-point accuracy worsened by 6.17 points vendor-reported; unverified — treat as an illustration of the risk, not a measured constant. The defensive practice is to evaluate:

  • Language-mix strata (ar, en, mixed) — Mizan derives lang_mix from approved spans;
  • Script-split WER and English-term preservation;
  • Switch-point error rate: compute errors only on tokens within ±k words of a language boundary in the reference (a PIER-style "points of interest" metric).

5.5 Points-of-interest and entity metrics

PIER (Point-of-Interest Error Rate) is a WER variant restricted to words of interest, motivated by the observation that ordinary metrics under-weight the points that matter in code-switched speech by averaging them with the dominant language. verified The same idea applies to any business-critical token class: numbers and amounts, names, product terms, dates. A practical recipe: tag these tokens in the gold set (or via regex/NER), align, and report an error rate over only those tokens. Decision makers care more about "did it get the amount right" than about filler words.

5.6 Multiple references and orthographic variants

PolyWER (Findings of EMNLP 2024) provides transliterated and translated alternative references so that valid variants are not penalized; earlier multi-reference WER did the same for dialectal Arabic spelling variants. verified When normalization cannot reasonably collapse the variants (English words in Arabic script; dialect spellings), score against the best-matching reference variant per word/segment, or maintain a project lexicon of accepted variants and apply it in the normalizer.

5.7 Beyond WER: semantic and task-level evaluation

WER treats every word equally and is insensitive to meaning; improving WER does not guarantee better downstream outcomes. Semantic Distance (SemDist) was proposed for downstream NLU tasks such as intent recognition and parsing, H_eval combines semantic distance with a non-keyword error rate, and embedding/LLM-based scoring is an active area with limited validation. verified (preprints) Recommended stance:

  • Keep WER/CER as the reproducible, comparable core. Add semantic or task metrics as a second opinion and validate them against human judgment on a small sample before trusting them.
  • If the transcript feeds a downstream system (search, summarization, intent detection, compliance flagging), measure that system's metric on transcripts from each candidate. It is the most decision-relevant number you can produce, and it is cheap once the transcripts exist.
  • If an LLM judge is used to grade transcripts, calibrate it (agreement with humans, position and verbosity bias) and never use it as the sole gate.

5.8 Timing, speaker and format metrics (out of scope for Mizan v1)

If word timestamps, diarization or punctuation/casing matter for your use case, evaluate them with their own metrics (timestamp deviation, DER, punctuation F1). Mizan reserves schema fields for diarization but does not evaluate it; do not infer anything about those capabilities from WER.

6. Statistical rigor: knowing whether a difference is real

6.1 Why intervals are not optional

Bisani & Ney's bootstrap paper (ICASSP 2004) asks exactly the question a swap raises: is an observed difference a genuine advantage or an effect of chance? Its finding was that confidence intervals on WER are wide and the large majority of improvements reported in the literature were not much bigger than the standard error. verified The simulation in §3.2 reproduces the point: at 100 segments a single WER carries about ±3.5 points.

6.2 Bootstrap confidence intervals

  1. Compute per-segment error counts (S+D+I) and reference length N for each system (these are the sufficient statistics for WER).
  2. Resample segments with replacement B times (B ≥ 1,000), and for each resample recompute the corpus-level ratio Σerrors / ΣN.
  3. Take the 2.5th and 97.5th percentiles (percentile interval) — or a bootstrap-t / BCa interval when the distribution is skewed.
  4. Seed the generator and store the seed so that the interval is reproducible (Mizan seeds per run and metric).
Segments are not independent Errors in segments from the same speaker, call or recording are positively correlated (same voice, same noise, same vocabulary). Resampling individual segments then understates uncertainty. Bisani & Ney found sentence-level resampling gives considerably smaller standard errors than speaker-level resampling; a later blockwise-bootstrap paper makes the same point for dependent utterances. verified Default to a cluster (block) bootstrap: resample whole recordings or speakers, then take all their segments. Use segment-level resampling only when each segment comes from a distinct speaker/recording. Mizan's report currently resamples segments; see §13.

6.3 Paired comparison of two systems

Because both systems transcribe the same segments, compare them paired:

for b in 1..B: draw one resample of segments (or clusters) # SAME indices for both systems d_b = WER_C(resample) − WER_I(resample) CI of the difference = [percentile 2.5, percentile 97.5] of d_b superiority: lower bound of (I − C) > 0 non-inferiority: upper bound of (C − I) < δ

Classical alternatives from speech recognition practice: McNemar's test (counts of segments where exactly one system is correct; appropriate when errors can be treated as independent events, e.g. isolated words) and the matched-pairs sentence-segment word error (MAPSSWE) test (which relaxes independence and suits connected speech) from Gillick & Cox (1989), both implemented in NIST's sclite/SCTK toolkit. verified The paired bootstrap is simpler to implement with arbitrary metrics and is the recommended default; use MAPSSWE as a cross-check when you want a classical, widely recognized test.

6.4 Non-inferiority and equivalence for swaps

  • Set δ first, from the business impact of an error-rate increase (e.g. "agents re-listen when WER > X") and from the human noise floor (§3.3). A margin below the noise floor is unfalsifiable.
  • Non-inferiority (cost-driven swap): pass if upper95%(WERC − WERI) < δ. This is stricter than "not significantly worse", which a small test set passes trivially — absence of evidence is not evidence of equivalence.
  • Equivalence (same model, new engine): two one-sided tests at 5% each, i.e. the 90% interval of the difference lies within ±δ.
  • Apply the criterion per critical slice, not only overall (§7), with a looser δ where slices are small.

6.5 Multiple comparisons and discipline

  • Pre-declare one primary metric (e.g. corpus WER after arabic_v1) and a short list of critical slices. Everything else is exploratory.
  • With K candidates, use Holm or Bonferroni adjustments for confirmatory pairwise claims, or rank candidates by interval overlap against the incumbent only.
  • Do not tune decoding parameters on the locked test set. A winner chosen as the best of many tuned variants has optimistic bias.
  • Repeat stochastic systems (sampling, temperature fallback): run ≥ 3 seeds and report variation; a difference smaller than the run-to-run variation is not a difference.

6.6 Percentiles and rates need intervals too

Latency percentiles, hallucination rate (a proportion on a small number of non-speech segments), error rate in load tests: all are estimates. Use Wilson/Clopper–Pearson intervals for proportions (a 0/40 hallucination rate is "≤ 8.8% at 95% confidence", not "zero") and bootstrap intervals for percentiles. State the sample size next to every figure.
